# Examples

What DONE looks like for every file the commands produce, taken from a demo build for a fictional Toronto plumbing business.
These are the quality bar, never the content. Nothing in here is real, and none of it belongs in a member's files.
Next: open the example that matches the file you are about to write, and match its shape.

## What each example shows

**keyword-map-example.md**
Root keywords, their clusters, search volume, difficulty and build order, all in one file. What `/keyword-research` produces.

**research-dossier-example.md**
The organised source material gathered before writing, covering all eight source types. What `/blog-post` collects first.

**website-index-example.md**
The page registry in use - what is live, what is approved, what still needs review.

**wordpress-blog-example.md**
A finished, publish-quality blog post. What `/blog-post` produces.

**wordpress-service-page-example.md**
A finished money page. What `/service-page` produces.

## The bar every example has to clear

Could a plumber with no SEO knowledge open this file and know what to do in ten seconds?

- Every number labelled in words - "2,400 searches a month", never a bare number.
- No abbreviations nobody taught them - no KD, CPC, SV, Vol.
- No status column repeating the same word down sixty rows.
- One block per thing, with air around it.

## Rules for using these

- These examples must match `references/file-examples.md`. That file is the spec, these are the worked proof. If an example drifts from the spec, the example is wrong - fix it, never copy its shape.
- When a member asks what a file should look like, show them the matching example.
- Never copy example content into a member's real files.
